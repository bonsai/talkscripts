# worktree の90秒解説

type: explainer
created: 2026-09-26
tags: [git, worktree, dev-workflow, parallel, agent, opencode, orochi]
related: [09-embed-layer-essay-20260924]

今回は、バージョン管理の worktree を90秒で説明します。

worktree は、ひとつのリポジトリから、作業フォルダを複数同時に生やせる仕組みです。ふだんブランチを切り替えると、開いているファイルが丸ごと入れ替わります。worktree ならブランチごとに別のフォルダを持てるので、切り替えが起きません。

やり方は3つだけ。まず、新しいフォルダとブランチを作るコマンド。次に、いまある作業フォルダを一覧するコマンド。最後に、不要になった作業フォルダを片付けるコマンドです。履歴やデータは共有されるので、丸ごと複製するよりずっと軽いです。

うれしいのは並行作業です。たとえば、ある作業がブランチの統合で忙しくても、別の作業を同時に進められます。同じ作業場所を触ると衝突しますが、フォルダを分ければ、競合も未保存の取り合いも起きません。

注意は2つ。同じブランチを二重に開けないこと。そして、これは同じリポジトリの別の出口にすぎないので、消し忘れに気をつけることです。

以上、worktree の90秒解説でした。
