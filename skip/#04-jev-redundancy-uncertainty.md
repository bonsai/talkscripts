# 冗長さを捨て、不確実性を数字にする — Jev 論

type: essay
created: 2026-09-24
tags: [jev, system-one, typesafe, llm, uncertainty, redundancy, decision-engine]
related: [09-jev-redundancy-uncertainty-essay-20260924, jev-deep-research-20260922, jev-semgrep]
duration_target: ~10min

LLM は賢い。だが賢いことと、ソフトウェアの中で信頼できることは別物だ。長く話せることは、しばしば長く迷い、長く嘘をつくことでもある。Jev の登場が刺さるのは、モデルがもっと賢くなったからではない。LLM が抱えていた冗長さと不確実性を、数字に落とし込む別の原語を持ち込んだからである。

---

生成モデルには、構造的に避けがたい二つの病がある。

ひとつは冗長さだ。問いはいかいいえでも、答えは段落になる。分類したいだけなのに、理由、前置き、謝罪、言い換えがついてくる。パイプラインの途中で、このメールは請求か技術か、と聞きたいだけなのに、毎回散文を吐き出しては JSON にパースし、パース失敗をリトライし、スキーマ外のキーに泣き、レイテンシとトークンを溶かす。知能のコストの大半が、**判断そのものではなく、判断の包装紙**に消える。

もうひとつは不確実性の不可視化だ。LLM は自信満々に誤る。温度を下げても、この答えがどのくらい当てになるかを、運用可能な形で取り出せないことが多い。人間は文面の勢いを確信度と取り違え、システムは成功レスポンスを正しさと取り違える。不確実性はあるのに、**数字として下流に渡せない**。だからゲートも、フォールバックも、人間エスカレーションも、勘で設計することになる。

冗長さはコストと複雑性を増やし、不可視の不確実性は事故を増やす。チャットには許されても、エージェントの内側、ルーティング、検疫、課金、権限の分岐には毒である。

---

Jev は、テキストを生成しない。state と型付きの問いを受け取り、Choice、Score、Noul といった閉じた答えだけを返す。確率と confidence が付き、1 リクエストで複数の問いを並列に評価できる。公称は数十から数百ミリ秒、入力は極端に安く、出力は実質無料に近い。

ここが本質だ。LLM が書いてから解釈するのに対し、Jev は最初から答えの空間を数学的に小さくしている。小さい空間では、スキーマ外の幻覚は起きようがない。冗長さは設計上消え、残るのは、どの選択肢か、どのくらいか、はいの確率はいくらか、という数字である。

言い換えれば、Jev は知能を会話から引き剥がし、**述語評価機**にした。チケットかける部門、ログかける要対応、イベントかける購買意欲。ソフトウェアが昔から欲しがっていた if の右側を、自然言語のまま、しかも確率付きで書けるようになった。

名前の由来も皮肉で正確だ。Jevons のパラドックス。効率が上がると消費が増える。判断が安く速くなると、判断の回数が爆発する。発表直後にゲートウェイ、エージェント、クローンが群がったのは、新しいチャットボットが欲しかったからではない。プログラムから呼べる決定の単価が崩れたからである。

---

冗長さの除去は、単に短く答えることではない。短文 LLM でも冗長さは残る。問題は長さではなく、答えが構造を持たないことにある。

Jev は冗長さを、次のような数字へ変換する。

有限個のラベルとその確率分布。ルーブリック上の離散スコア。命題の成立確率、ゼロからイチ。

たぶん請求まわりだと思いますが、場合によっては、という散文は消える。代わりに、請求の確率がゼロ点八一と出る。下流は閾値で切れる。A/B できる。集計できる。キャッシュできる。同じ問いを一万イベントに当ててヒストグラムが描ける。生成の一回性が、**測定可能な判定**に変わる。

ここに、アナリティクスや意味 grep が乗る必然がある。生成は物語を増やすが、判定は地図を増やす。地図は重ねられる。物語は毎回書き直される。

---

不確実性を消すのではない。**見える化し、運用の変数にする**のだ。

校正の約束はざっくりこうだ。モデルがゼロ点九と言った判断は、母集団ではおおよそ九割当たってほしい。個別の一発保証ではない。だがパイプライン設計者には十分強い。confidence が高ければ自動実行、中間なら LLM やルールにフォールバック、低ければ人間。という分岐が、文学ではなく数値で書ける。

LLM の不確実性は、しばしばそれっぽさの中に溶ける。Jev の不確実性は、確率と confidence という二つの軸に射影される。完全ではない。公式自身が、文字通りの読解、弱い算術、日付、間接質問、コンテクストの劣化、敵対入力などを列挙している。だが欠陥が列挙可能であること自体が、生成モデルのなんとなく不安より工学的だ。不安は設計できない。分布は設計できる。

重要な注意がある。**型が正しいことと、意味が正しいことは別**だ。部門は請求、と綺麗な形で返ってきても、中身は技術かもしれない。スキーマ検証を正しさと同一視してはいけない。Jev が潰すのは冗長さと形の不確実性であり、世界認識の誤りまでは消えない。数字に落としても、その数字が指す事実は、なお検証の対象である。

---

ChatGPT 以降の十年は、生成を万民のインターフェースにした。その成功の裏で、ソフトウェア内部は逆に苦しくなった。エージェントは話しすぎ、ツールはパースしすぎ、コストは前置きに消え、失敗は自信満々に見える。

Jev の登場は、その反転に見える。RLHF の系譜から出て、チャット用 RLHF の対極を標榜する判断モデル。カーネマンの System 1 を名乗り、速い直感を API にした。マークシートが記述式を殺したわけではないように、Jev も LLM を殺さない。記述式が必要な場所は残る。だが採点、振り分け、ゲート、探索まで全部記述式でやっていた時代は、冗長だった。

正規表現の発明が検索とは何かを更新したように、命題評価機の普及は自動化とは何かを更新する。自動化の本丸は文章生成ではなく、**安全に呼べる決定**だった、という再発見である。

---

LLM の得意は、生成、要約、多段推論、曖昧な相談。出力は開いたテキスト。冗長さは構造的に抱えやすく、不確実性は文面に溶け、リスクは形も中身も壊れうることだ。

対して Jev の得意は、分類、ルーティング、ゲート、意味マッチ。出力は閉じた型と確率。冗長さは設計上ほぼ排除され、不確実性は数字として渡せる。リスクは形は壊れにくいが、中身はなお誤りうること。

トータルの命題は短い。**LLM の冗長さは出力空間が開いていることの税金であり、不確実性は校正されない自信の税金である。Jev はその両方を、閉じた答えと確率という数字に射影する。**

射影は圧縮だ。圧縮には情報損失がある。だから算術も、詩も、交渉も、まだ LLM の領分だ。しかしソフトウェアが一秒に千回欲しがるのは詩ではない。半分はこれかあれかであり、もう半分はどのくらい確かそうかである。そこに数字が来た。

歴史が繰り返すとすれば、次に起きるのは予測どおりだ。判断が安くなれば、判断は増える。増えた判断は、また新しい冗長さと新しい不確実性を生む。どの閾値で切るか、どの定式化で聞くか、どの confidence で人に渡すか。Jevons の名を冠したモデルが、そのパラドックスの入口に立っているのは、ほとんど出来すぎたくらい正確である。

冗長さを捨てよ。不確実性を隠せ。ではなく、**測れ。**

Jev が示したのは、そのための単位だった。
