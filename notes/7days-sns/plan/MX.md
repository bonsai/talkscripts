# MX（Marketing Transformation）実装——『DQ 7日で理解するSNS開発』

MX = 市場を観測し、顧客との関係を設計し、仮説・施策・反応・学習を循環させる実践モデル。
Marketer = 市場との関係を設計・観測・更新する人。

## Cycle

```
observe ──→ segment ──→ hypothesize ──→ position ──→ communicate ──→ measure ──→ learn ──→ update
   │        │               │              │              │                │          │           │
   └────────┴───────────────┴──────────────┴──────────────┴────────────────┴──────────┴───────→ market
```

## observe（観測）
- テック書籍市場：技術書典は毎回入場殺到・AI／フレームワーク入門の同人誌が売れ筋
- 「SNSを作る」「TypeScript×Next.js」「AI機能の組み込み（RAG・LLM）」「型安全」で検索需要が高い
- 従来の入門書は「厚い・教科書調・書いて終わり」、実行/答えまで至らない
- 我々の既存資産：Webフレームワーク連載14本（Django/Flask/NEXT.js、DB、LLM、OpenAPI、frourio、Hono、デプロイ）＋プラトン対話劇という差別化ネタ

## segment（区分・セグメント）
1. **高校生**（技術部・文化祭SNS）＝成果物ドリブン
2. **退職者**（教養として）＝読み物ドリブン
3. **駆け出し〜中級エンジニア**（技術選定に迷う）＝答えドリブン ← 最も買いやすい
4. 学習用AI需要層（Cursor/Claude Code入門）※将来

## hypothesize（仮説）
- H1：**「DQ＝デベロッパークエスチョン」で各章を問いの形にし、章末に答えを1文置く**形式が、既存入門書との差別化になる
- H2：**100円で「答えだけ」を先出し**すれば、詳細・実装が欲しい層は980円版を買う（ファネル転換が高い）
- H3：同一原本を読者別にローカライズすれば、1本書きで2〜3セグメントを同時に攻略できる
- H4：Vol.1（土台）+ Vol.2（AI）の2冊構成は、AI本ブームの中で「土台からの一気通貫」として差別化可能

## position（ポジショニング）
- 本の立ち位置：**「技術選定に迷う開発者のための、答え先行のSNS開発入門」**
- 競合との差：①章＝DQ（読みたくなる問い）②章末＝答え（結論先行）③プラトン対話劇（読み物）④2読者ローカライズ
- 同一ポジション文章（帯案）：『Django？Next.js？ 迷ったまま作るな。7日で、選べて、動くSNSができる。』

## communicate（コミュニケーション）
- チャネル：技術ブログ（現連載：14本を改稿し予告・抜粋記事化）→ X（Twitter）／ note・Zenn → 技術書典ブース（100円版を配布・実物を置く）→ BOOTH・KDP
- メッセージ：各DQタイトルで「引っかける」（例：『SNS開発のフレームワーク、どれを選ぶ？』）。答えだけの1文をToCとして公開
- 発信パルス：出展1ヶ月前から毎日1DQずつ公開→当日に"答え"へ誘導

## measure（計測）
- 100円版DL数、100円→980円転換率、BOOTH導線ごとのCVR
- 技術書典での販売冊数・アンケート（どの層が買ったか）
- 記事が章として読まれる率（離脱ポイント：各DQページ滞在）
- レビュー・書評数、Xの拡散（具体的なDQがバズるか）

## learn（学習）
- 読まれたDQ／読まれなかったDQを原本へフィードバック（タイトル差し替え）
- 「答えだけ」に対する反応→100円版の内容・価格調整
- 購入層アンケート→次のsegment（例：AI学習需要層）の開拓判断

## update（更新）
- 原本（共通核）へ反映 → ローカライズ差分（帯・まえがき・コラム）を再適用
- 構成・価格・バンドル（100円→500円→980円→1,700円セット）を市場反応で改訂
- MXの次のターンへ：observeに戻る（市場の変化を常時観測し続ける）
